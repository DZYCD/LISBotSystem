# 项目经历：基于多智能体协作架构的 LIS 知识图书馆系统与底层 Agent Harness 构建

## 一、项目标题

**《LIS（World's Memory Library）世忆知识图书馆：面向多智能体协作的分布式 Agent 系统与安全 Harness 底层构建》**

（副标题 / 备选：《多智能体（Multi-Agent）委托链协作架构 + 可学习 Agent Harness 安全骨架，从零自研的 LLM Agent 平台》）

---

## 二、项目概述

本项目从**零**构建了一套面向"知识图书馆"业务场景的多智能体（Multi-Agent）协作平台，包含 **Agent 底层框架（Harness）** 与 **多节点协作通信协议（TLL v2）** 两层。系统由多个职责分明的机器人（EiAr 编程助手族 / SaYi 调度族 / Skaye 监控族）组成，每个机器人是一个独立 LLM 驱动的 Agent 节点，通过统一委托链模型协作完成复杂任务。

本项目已产出**多篇软件著作权与专利**，并作为**当前研究论文课题**的核心实验平台。

## 四、详细设计

### 4.1 底层 Agent Harness（LLM 的内在）

从零复刻了 deepseek-harness 的「执行前审批 + 每次调用动态解析的范围策略 + 受保护执行管线」安全骨架：

- **Agent 多步推理引擎**：核心是 `while` 循环——LLM 生成文本或 tool-call → 执行工具 → 结果写回会话 → 喂回模型继续推理，直到不再调用工具。支持多步 Tool Use、失败闭环（工具失败也写回供模型自纠）。
- **安全执行管线**：每次工具调用经过「审批决策（allow/deny）+ 动态沙箱范围策略 + 能力后端执行」三层受保护管线，杜绝模型越权。
- **能力后端 seam（implements 路由）**：工具通过 YAML 声明（`implements` 字段）路由到不同后端——`local`（文件操作）、`skill:<name>`（技能动态加载）、`code`（沙箱代码执行）、`contact`（跨族牵线接口）。实现了"双轨"注册：YAML 声明 + Python 实现，单一来源。
- **Windows Job Object 沙箱**：用 Job 对象治理真实子进程（进程数/内存/超时强制终止），实现安全的代码执行（`run_code` 沙箱运行 Python/shell，捕获 stdout/stderr/exit_code）。
- **会话记忆（Memory）**：按对话方维护持久会话，跨消息上下文；记忆压缩机制沉淀长期知识。
- **分层系统提示词**：利用 LLM prompt caching，把稳定层（角色/工具）放前缀、变化层（会话）放末尾，最大化缓存命中率、降本提速。
- **技能加载器**：从 `skills/` 目录动态注册工具（单一来源），支持热重载。

### 4.2 多节点协作协议（LLM 的社区）

设计了**统一委托链模型**，让多个 Agent 节点组成协作社区：

- **委托 = 网络工具**：任意节点需要别的机器人做事，用 `task_create` 网络工具发委托；本地能做的用本地工具（本机直用，不走网络）。
- **TASK id 复用 + 回环检测**：委托链沿途复用同一 task_id 便于追踪；`_in_flight` 集合 + 挂起检测防止委托回环（A→B→A 死循环）；**禁止自我网络委托**（to==自己直接拒绝）。
- **Trace 委托链轨迹**：`Trace.add_hop` 记录每一跳（`delegate_to_<bot>` / `return_to_<bot>`），完整还原委托链（含逐跳回传），用于追踪与可视化。
- **同步阻塞回传**：委托后 `asyncio.wait_for` 阻塞等回传，被委托方处理完回传，pending future 填充唤醒。
- **中央汇聚（Skaye_SV）**：中央节点作为注册中心——机器人启动上报注册信息、ping 心跳握手、任务活动档集中存档；大屏动态从注册表读取，非硬编码机器人列表。
- **上报/握手**：ping 返回完整注册信息（网络/组别/可联系机器人/搭档/自身工具含参数），握手时间随 ping 更新，支持定点 ping。
- **孤岛隔离 + 牵线搭桥**：EiAr 与 SaYi 默认隔离互不知晓，仅"合作"时由 Skaye 族牵线建立联系（写入 bot.yaml，热重载 peers），实现最小权限、按需协作。
- **监控可视化大屏**：Canvas 星空节点图按组配色，点击节点/任务动态绘制委托链（委托蓝 / 回传绿 / 留档上报橙），展示工具调用日志与对话结果；提供对话框以中央调度身份发起 chat 委托。

### 4.3 RAG 检索增强生成（Agent 记忆检索）

为 `memory_query` 工具落地了**真正的向量检索增强生成（RAG）**：

- **语义向量化**：复用已有 torch 环境（ultralytics conda 虚拟环境），用 `sentence-transformers` + **BGE 中文语义模型**（512 维向量）对知识库内容 embedding 化。
- **Embedding 微服务化**：由于主项目 Python 3.14 无法直接 import 其他 conda 环境的 torch（C 扩展版本绑定），把 embedding 抽成**独立 HTTP 微服务**（`embedding_server.py`），主项目通过标准库 urllib 调用做向量化。**模型缓存放 D 盘**，避开 C 盘空间不足。
- **混合检索**：以**向量余弦相似度为主判据**（相关条目相似度 ≥0.59、无关 ≤0.43，阈值过滤不误召回），**关键词命中为辅助加权**排序，显著提升记忆召回准确率（尤其语义相近但字面不同的查询，如"徐州气温"→"徐州天气"）。
- **Agent 自主检索**：LLM 通过 `memory_query` 工具自主语义查询知识库，跨会话记忆按需注入上下文。
- **降级容错**：embedding 服务离线时自动退回纯关键词检索，不崩溃。

### 4.4 端到端业务验证

- **真实 LLM + 真实 MQTT** 全链路跑通：web 对话框 → 委托链 → 目标 Agent 联网调天气 API → 回传 → 大屏存档展示（完整验证了"写代码 + 沙箱执行 + 联网获取实时数据 + 多跳委托"）。
- 修复了多个生产级问题：MQTT client_id 被 broker 拒绝（rc=5）、子进程 GBK 解码中文乱码、web 分身绕过委托链导致回传丢失、无 LLM 节点误走 LLM 报错等。

## 五、核心技术亮点 / 成果

1. **自研 Agent 安全 Harness**：从零构建可学习的 agent 骨架，完整复刻业界主流 harness 的审批+沙箱机制，体现扎实的系统设计能力。
2. **统一多智能体协作模型**：提出"委托=网络工具、复核=等结果那轮 LLM、委托链=嵌套 LLM 循环栈、同步阻塞等回传"的清晰抽象，支撑多 Agent 编排。
3. **安全沙箱代码执行**：Windows Job Object 实现真实子进程资源治理与超时强杀，是 Agent 自主执行代码的安全底座。
4. **RAG 向量检索增强**：BGE 语义向量 + 余弦相似度 + 混合检索（向量+关键词），embedding 微服务化复用已有 torch 环境、模型缓存 D 盘，实现 Agent 记忆的语义召回（"徐州气温"→"徐州天气"）。
5. **配置驱动 + 规则化**：工具/机器人/网络配置全部 YAML 化（`bot.yaml` 存联系方式、`tools.yaml` 存工具），代码是纯框架不硬编码，体现工程规范。
6. **AI 工具深度使用**：全程使用 AI 编程工具（Cursor / Claude Code 类）辅助设计、编码、排障，加速开发迭代。
7. **已产出多篇软著与专利，应用于当前研究论文课题**。
